# 自动整理与查询扩展

日常步骤不自动检索历史记忆。角色通过 `memory_recall` 使用 SQLite FTS5 trigram、`Intl.Segmenter` 中文分词、别名及人物、会话、情境和时间过滤。默认 `semantic=false`；明确需要模型扩展检索词时使用 `semantic=true`。成功扩展词按角色、提供商、模型与查询缓存二十四小时，查询结果读取当前数据库。

`memory_recall` 返回 `{items,nextCursor}`，默认十条、最多五十条，每条命中片段最多256个估算 Token；整页受现有工具预览预算约束。游标绑定查询条件和检索数据版本，资料变化后重新查询。`memory_read` 按真实标识读取正文，`source="history"` 和 `source="sources"` 分页读取历史和来源；大正文提供 `payload_read`。Panel 默认使用本地检索，游标失效时保留已显示结果。

自动整理每天02:00到期，使用KW_TIME_ZONE，默认Asia/Shanghai。Host每分钟核对日期，在角色空闲、已启用且允许执行时启动，每个角色每天最多领取一次。忙碌、暂停、额度限制或维护会顺延到可执行时。活动结束不触发整理。首次在白天升级时等待次日02:00，重启不会重复当天已经领取的整理。管理入口 `memory.consolidate` 保留手动整理能力。

整理开始后捕获本次经历的接收上界。后续消息继续进入角色，已经开始的整理不会被消息取消。暂停、停止、会话管理和维护仍取消并等待整理结束。记忆、人格和连续性在事务中检查当前版本；后台修订不关联到后来开始的活动。

每批只选择与来源内容、人物或共同来源相关的旧认识，最多十二条记忆和六条连续性资料，当前生活也须相关才能入选。旧资料提供必要字段，完整来源和修订历史由宿主保存和校验。角色边界放在固定前缀，候选、来源和错误反馈放在后面。已有输入预算覆盖实际消息，不以无关资料填充。旧分片保留既有位置与校验和。

内部工具调度、Skill 指导和没有文字内容的内部输出持续保存，直接推进整理位置。有内容的内部文字保持主观来源，实际观察与媒体理解继续参与整理。模型将同一事情的来源合并，选择有长期价值的变化，已有认识没有变化时可以返回空修改。

提取和修正始终输出同一种业务对象：`{memories,continuity,reason,persona?,selfState?}`。新建提供必要业务字段，修改使用真实标识、修订号及变化字段。宿主补全默认字段、未变内容和旧来源，然后执行完整 Schema、来源与版本检查。原始输出、草稿、修正输入、用量和结果持续保存，全部变更与分片进度在同一事务提交。

每批保存固定来源、输入版本、协议、草稿、请求及提交进度，不混入后续事件。每轮最多一次提取和一次修正；自动整理失败或中断的未完成部分留到下一天02:00继续，当天不因退避时间到达额外发起自动请求。手动整理仍遵守批次的退避限制。重启复用已保存的完整模型响应；未保存结果的请求保持未知。版本冲突重新读取涉及记录，再使用同一来源生成修改。数据库及负载保存错误终止相关活动。

验证命令：`node scripts/verify-memory-demand.mjs`，使用本地配置的 workbuddy2api、独立数据目录、真实 Harness 和社交发送守卫，检查问候、主动查询、来源读取、整理幂等及重启。`node scripts/verify-auxiliary-cost.mjs` 保留官方模型与可选真实失败案例验证。

`node scripts/admin.mjs usage.report '{"since":"2026-11-09T00:00:00+08:00"}'` 按实际提供商、模型与用途汇总主对话、整理、查询扩展、角色生成和 Harness 压缩用量。可提供 roleId 和 until。报告包含未缓存输入、缓存读取、输出、失败次数及缺失用量的请求，缺失路由标记 unknown，实际费用以供应商账单为准。
