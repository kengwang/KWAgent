# 自动整理与查询扩展

日常步骤背景使用 SQLite、FTS5 和 `Intl.Segmenter` 中文分词检索，不发起辅助模型请求。`memory_recall` 默认 `semantic=false`；明确需要模型扩展检索词时使用 `semantic=true`。成功扩展词按角色、提供商、模型与查询缓存二十四小时，读取结果时仍查询当前数据库，新增记忆立即可检索。

自动整理在角色空闲时合并尚未整理的经历。达到十六条可整理事件或最早事件等待六十秒后具备启动条件；每分钟维护检查也会推进零散输入，因此少量输入通常在一至两分钟内开始整理。前台持续运行时可以延后，原始事件始终先保存。管理入口 `memory.consolidate` 可以立即整理。

整理开始后捕获本次经历的接收上界。后续消息继续进入角色，已经开始的整理不会被消息取消。暂停、停止、会话管理和维护仍取消并等待整理结束。记忆、人格和连续性在事务中检查当前版本；后台修订不关联到后来开始的活动。

每批只选择与来源内容、人物或共同来源相关的旧认识，最多十二条记忆和十二条连续性资料。当前生活优先参与候选。既有输入预算仍覆盖实际消息，未使用空间不以无关资料填充。新的来源视图去掉接收序号等管理字段，旧分片继续使用既有位置与校验和。

内部工具调度、Skill 指导和没有文字内容的内部输出持续保存，直接推进整理位置。有内容的内部文字保持主观来源，实际观察与媒体理解继续参与整理。模型将同一事情的来源合并，选择有长期价值的变化，已有认识没有变化时可以返回空修改。

格式补全仅使用宿主已经知道的信息，例如空数组、输入中已有记录的版本和批次理由。未知记录、无效来源、未经确认的执行和实际版本冲突仍须校验。可修复的草稿在容量允许时通过 JSON Patch 修正出错字段；没有完整草稿或来源版本已经变化时重新提取。原始输出、修正输入、用量和结果均记录。所有拟提交修改与分片进度仍在同一事务提交。

连续失败不会每分钟重复三次请求。一次整理最多三次尝试，之后依次等待一分钟、四分钟、十六分钟和一小时，保留待处理来源和失败依据。数据库及负载保存错误继续终止相关活动。

验证命令：`node scripts/verify-auxiliary-cost.mjs`，需要本地配置可用的官方 Flash 及相应 Harness 提供商。可选 `KW_AUXILIARY_REPAIR_SAMPLE` 指向本地保存的真实失败案例，用于验证局部修正。验收使用隔离数据目录、真实数据库、实际模型与社交发送守卫。
