# 对话重置与角色删除

选择 Panel 左侧角色后，顶部提供“重置对话”和“删除角色”，确认后执行。确认界面持有当前修订号；如果其他操作已更新角色，会要求读取当前版本后重新确认。

## 重置对话

创建新的 Harness Session，保留初始设定、当前人格、自我状态、记忆、关系、世界认识、群聊与私聊绑定、生活资料及 KWAgent 目标和计划。原有启用、暂停、停止或未启用状态保持不变。

当前活动与所属后台任务停止，旧会话归档。旧会话中的原生 Harness 提醒停止；通过 `life_plan` 保存的安排按角色状态重新登记到新会话。新对话不自动附带此前近期聊天与发送记录，长期记忆和来源仍可检索；结果未知的操作继续提供核实背景。

尚未被旧 Session 接纳的事件继续保留，新会话重新生成对应感知视图。旧感知保持不可变。已接纳和已完成的输入不重复投递，历史工具操作不会重放。

在 Harness 侧栏归档角色当前会话时，KWAgent 自动执行上述切换。应用关闭期间发生的归档在启动时修复。归档前为停止状态的角色继续保持停止。

## 删除角色

删除操作依次停止活动、取消目标与安排、停用角色扩展、归档所属会话并释放群聊与私聊绑定。角色从当前列表移除。原始经历、完整负载、记忆、来源、发送回执与修订历史继续保留，历史详情仍可读取。

角色 ID 保留用于历史归属，重新创建角色需要新的 ID。删除完成后新事件根据当前绑定规则分配，既有经历不会转移给其他角色。

浏览器扩展需要重启才能停用时，删除操作保持未完成，相关角色保持暂停；重启后继续同一操作。失败可以在 Panel 读取当前角色版本后重试。操作日志固定目标 Session，进程中断后恢复同一次变更。

## 管理命令

先读取当前修订号：

```sh
node scripts/admin.mjs role.read '{"roleId":"角色ID"}'
```

使用返回的 `revision`，通过文件提交操作，适用于 Windows 和 Linux。下面的 `1` 替换为实际修订号：

```json
{"id":"角色ID","expectedRevision":1}
```

```sh
node scripts/admin.mjs role.reset @reset-role.json
node scripts/admin.mjs role.delete @delete-role.json
```

历史 Session 查询可显式提供原 Session 标识，并核验所属角色：

```sh
node scripts/admin.mjs session.records '{"roleId":"角色ID","sessionId":"原Session标识","limit":50}'
```

数据库使用 Schema 4，兼容读取旧角色。升级前创建完整备份，Schema 3 到 4 迁移另外保存 SQLite 一致快照；恢复旧镜像时使用对应版本备份。
