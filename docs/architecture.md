# 运行与持久化

## 负载与预算

Schema 2 在升级前使用 SQLite 一致快照保存 Schema 1 数据库。原始记录继续保留，新增负载引用、不可变感知批次、活动关联和整理分片进度。旧记录缺少的关联显示“未记录”。

`artifacts/` 保存 SHA-256 寻址的完整 JSON 对象；对象完成原子落盘后才提交数据库引用。同一内容可以拥有多个独立的角色及来源授权。`payload_read` 按 UTF-8 字节游标读取，校验角色归属并响应取消。对象目录参与完整备份、校验和恢复。

Harness 的估算机制统一计算感知、记忆与工具预览预算。默认感知 8192 Token、整理输入 16384 Token、工具预览 2048 Token；Panel 每条正文预览 4 KiB、状态快照 512 KiB。二进制编码在预览中只保留元数据，完整对象仍可读取。预算可以通过 `.env.example` 中的部署参数调整。

## 角色

每个角色使用一个长期 Harness Session。明确群聊绑定优先于账号全局绑定，联系人绑定优先于默认私聊角色。绑定修改影响后续事件。人工可以向其他角色迁移尚未进入活动的经历，已进入活动的经历通过来源引用保留。

角色支持重置对话、归档后自动切换 Session 和保留历史的删除，使用 Schema 4 与持久操作日志协调。新 Session 重新装配未接纳的原始事件；普通重启保持已有批次不变。具体规则见 [角色管理](role-lifecycle.md)。

角色状态与当前活动状态分别保存。暂停和停止均保留经历，时间事项暂停投递，模型调用前和工具执行前再次检查状态。后台检查负责发现额度重置和活动时段重新开始。

一秒合并窗口从首条待处理事件开始计算。已经准备投递的批次保存稳定消息标识，恢复时核对 Harness 的持久 inbox 与已接受输入，随后处理新事件。后台任务完成、条件候选和人工输入均可以形成感知。

全部接入能力使用 Harness 的固定 PTC 工具模式。角色管理员、实际消息发送者和事项来源写入每步背景，由模型依据提示词判断请求。工具目录不按 QQ 身份过滤或切换；消息进度通过活动记录展示。

已产生完整模型响应的步骤结束时，相关输入登记为已处理，投递状态不再被后到的回执降级。重复事件、重连及重启先检查处理记录与 Session；已经接纳或处理的消息不会再装配新的感知、查询背景或唤醒。未接纳的输入继续保留。

角色的前台回合确认投递并刷新Session。记忆模型在每天02:00到期后以独立后台工作整理，新输入继续进入前台处理；暂停、删除和维护会取消并等待后台任务释放资源。历史记忆通过工具按需查询，步骤背景提供当前状态和本次唤醒直接关联的事项。

`kw-lagrange` 根据真实协议字段整理会话、账号身份、昵称来源、提及、引用、嵌套转发和附件读取状态；内容理解与话题判断由角色决定。`kw-life` 优先选择当前会话的近期经历，固定 `PerceptionFrame` 的来源、整理版本、读取引用和实际预算。已经准备的批次恢复时继续使用原内容和消息标识。

一次 Harness turn 对应一项活动，以 Session 标识和 turn 起始记录确定身份。只有真实的 `user/message` 提交后，输入与经历才进入该活动；排队与已接纳状态分别显示。模型步骤、工具及 PTC 子调用通过 `callId`、`rootCallId` 与回执、修订、后续安排关联。接收新输入可以继续同一活动。活动结果保留发送成功、失败、结果未知以及中断等事实。

每次工具执行另外使用宿主的 opaque token 分配独立执行标识，经历与回执按该标识关联。不同角色、模型步骤或后续活动复用相同 `callId` 时仍保留独立结果，原始 `callId` 与 `rootCallId` 同时保留。

连续三次相同工具、参数与结果只产生一次状态提醒。PTC 的父调用与子调用分别关联，提醒不重复计算父调用，也不改变原执行结果。全部新 Session 读取使用公开 `sessionQuery`，上下文与负载引用通过公开插件记录保存。

延迟一次的事项保存为绝对到期时间。暂停后恢复时，已经到期的单次事项立即重新安排；周期事项继续后续时间规则。时间事项的完成状态表示本次唤醒已被接收，具体目标是否完成由角色另外确认。重复事项投递按计划和发生时间识别。

## 记忆

SQLite 保存原始事件、长期认识、来源与修订历史，FTS5 提供文本检索，角色当前模型扩展检索表达。人物、类型、时间、情境和归属在查询中执行过滤。

`memory_recall` 的 `semantic` 参数控制是否由当前模型扩展查询词；`false` 执行直接检索。`memory_read` 阅读具体条目或来源，`memory_revise` 使用修订号提交变化。

记忆整理使用当前角色模型，保存真实输入、输出和用量。原始经历持续保留，整理可以合并或修订认识。发生人工编辑冲突时重新读取当前版本。上下文压缩前写入原始经历的持久化检查点，由 Harness 继续摘要；后台整理保留未完成进度。

每次整理处理固定上界内的未处理经历，模型请求在事务外执行。活动内部文字、实际工具结果和媒体处理状态同样保存。JSON 表达可以修复，字段、来源、版本和状态仍严格校验；有限重试后仍不成立的输出进入待整理状态，原始经历及未提交分片保持完整，空闲后重试。查询扩展失败时使用真实文本检索结果，并保留失败与模式记录。数据库和负载持久化失败仍停止依赖该状态的活动。

长来源按固定字符边界分片，边界与校验和持续保存。中断后只处理尚未提交的分片，全部分片提交后才将经历标记为已整理。磁盘引用先读取完整对象再生成来源视图，二进制内容只提供元数据；模型输入、输出及用量均保留。已有记忆按剩余预算选择，必需人格与来源超过容量时明确失败。

纯内部资料读取、修订及 PTC 包装记录不会再次触发模型提取，原文与已有实际子调用记录继续保留。已有未完成分片保持原始视图与位置。

每个模型步骤冻结一份人格、目标、记忆版本与输入标识，实际装配和 Session 记录使用同一份快照。人工编辑从后续步骤生效。`self_revise` 使用真实经历、修订号与理由更新人格、自我状态和表达示例；示例只作为风格上下文。人格修订保存结构化来源，原始设定持续保留。

下一步骤准备完成后，`kw-life` 通过公开的 Session surface replacement 移除此前 `kw-life-state` 正文，保留同一运行背景中的其他插件贡献。新请求只携带当前步骤背景；原始消息、工具结果、不可变快照和上下文引用继续保存在 Session 与负载对象中。恢复时只检查当前 surface，无需扫描完整日志。上下文压缩和模型输出容量沿用 Harness 的原生策略。

## 事件与工具

MCP 和 SSE 连接分别管理。事件先保存，再投递给角色。消息根据账号、会话和序号去重；历史核对位置与实时最大位置分开保存。群聊采用序号补齐，私聊采用漫游游标核对。不可恢复的非消息事件记录接收空缺。

具有副作用的调用先保存意图，再保存回执。超时和进程终止会保留结果未知状态。重复调用可能产生新的远程效果。

能力目录独立记录远端 Schema、接入策略与当前账号最近调用证据。输入或输出 Schema 校验失败记录具体阶段；失败不会永久改变支持声明。`capability_read` 与 Panel 读取同一目录，Skill 指向该目录获取实际参数。目录更新不发送探测消息，Markdown 发送在所有相关发送工具及嵌套转发节点中明确拒绝。

接收附件在后台保存原始内容和来源，媒体理解由角色按需调用。资源地址通过实际资源标识刷新。图片理解默认使用配置的视觉连接，视觉配置可以继承聊天模型；视频抽帧与音轨提取使用 FFmpeg。QQ 语音转写需要原始 QQ 语音消息，本地音轨需要另外接入支持文件输入的语音识别能力。

## 扩展

角色扩展使用独立目录和 Bun 锁文件。入口使用 Node ESM。纯 Host 扩展附着到角色 Context；包含 Client 的扩展声明正式 bundle，以 profile 插件加载浏览器入口。扩展包名称需要在当前 profile 中保持独立。

扩展依赖由 Bun 安装，profile 登记、解析和加载使用 Harness 的公开 Interface。更新已启用扩展前先停用，安装使用新的版本目录。

容器中的所有角色共用 `/data/python/.venv`，通过 uv 管理依赖，角色并行准备时共用同一次初始化。环境继承镜像提供的只读 Python Playwright 基础依赖。Chromium 二进制随镜像发布，共享环境进入完整备份；浏览器 profile、脚本与输出保留在各自工作目录。固定系统段告知实际解释器路径与用法，工具执行继续沿用 Harness 的现有入口。

暂停或维护会释放角色 Host 扩展，恢复时重新挂载。HMR 返回的待重启状态保存在扩展记录中。模型请求、记忆整理和压缩等辅助请求共用角色用量统计。

扩展启停先保存期望状态。纯 Host 扩展通过角色 Context 挂载和释放；浏览器扩展更新 profile 后通过 HMR 重组。KWAgent 自身运行文件发生变化时，浏览器扩展登记保存为待重启，避免在登记过程中卸载当前管理服务。

## Panel

Panel 的查询、变更和状态流使用严格 Typert wire schema，同一份 schema 用于 Host 和 Client。浏览器依赖通过公开模块表共享，输出为 lazy-CJS factory。

状态流先建立订阅再读取快照，提交后的变化通知触发新快照。人工编辑携带 `expectedRevision`，冲突保留当前数据供重新提交。

订阅只发送有界摘要。活动、人物、来源、历史及能力查询默认每页 50 条，上限 200 条，返回后续游标。正文、原始版本与负载单独读取，编辑前获取完整内容。人物使用账号聚合有来源的别名、认识、关系与共同经历，世界条目使用同一套来源浏览。来源详情可以逐级读取并返回上一项。

读取后续页时保留当前历史视图，使用“刷新列表”接收新变化，其他角色的修订不会清空已读取内容。人物昵称只从带来源的发言人资料取得，记忆关键词单独保留。工具或操作中的嵌套负载引用提供经过归属检查的继续读取入口。

管理修改在备份切点前完成；维护期间停止新的修改和角色活动，接收器继续保存外部事件。数据库关闭前等待事件接收器、角色和进行中的整理完成。
