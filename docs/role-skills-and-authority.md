# 角色 Skill、身份与管理员

## 预注入 Skill

Panel 的“编辑角色”提供 `preinjectSkills` 列表，每行填写一个 Skill 名称，例如：

```text
kwagent-life
lagrange
humanizer
```

每个模型步骤通过 Harness 注册表读取该角色作用域及工作目录中的 Skill，使用宿主的标准格式注入完整正文。内容、资源路径、提供者和摘要与当前人格一起冻结并写入 Session 引用。修改从下一步骤生效；参考资料继续按需读取。缺失或不允许模型读取的 Skill 明确报告。

## 从 GitHub 导入

在“能力 → 角色 Skill”填写仓库地址、Skill 子目录和可选的分支或标签。例如：

```text
仓库：https://github.com/Aboudjem/humanizer-skill
子目录：skills/humanizer
```

导入保存实际提交、来源和角色目录，使用 Harness 文件系统 provider 校验 `SKILL.md`，复制 Skill 目录及参考文件。资料存放在当前角色工作目录的 `.agents/skills/`，独立参与备份和恢复。同名目录不会被覆盖；仓库脚本不会因导入而执行。

导入后将实际名称加入该角色的预注入列表。管理端也可调用：

```sh
node scripts/admin.mjs skill.install '{"roleId":"角色ID","repository":"https://github.com/Aboudjem/humanizer-skill","path":"skills/humanizer"}'
node scripts/admin.mjs skill.list '{"roleId":"角色ID"}'
```

## 身份与角色表达

首次推理前查询实际登录 QQ，并提供昵称、观察时间与工具来源；涉及群聊时读取自己的群名片，无法取得的资料明确标记未知。提及、引用和私聊按账号身份识别，昵称相近的人保持独立。

角色以初始设定为边界，延续当前人格及世界情境，对外保持角色表达。宿主信息用于内部正确操作，表达 Skill 服务于角色风格。发送入口会拒绝明确跳出角色的模型身份自称，保留正常角色发言和引述。

## 角色管理员

`adminQQs` 在 Panel 单独配置，可以填写多个 QQ。空列表不会授予任何群友危险操作权限。群主、群管理员、昵称、提及、引用与转发中声明的账号都不能代替实际消息发送者。

普通交流可以使用社交发送、只读资料查询、角色自己的记忆和计划等能力；群管理、账号修改、宿主代码执行、安装扩展及访问其他宿主目录需要角色管理员的明确请求。程序在工具执行前核验当前权限，嵌套调用仍经过同一检查。

受限场合使用直接工具调用，避免通过任意 Node 程序越过工具边界。管理员请求保留来源并可使用完整能力；撤销 QQ 配置会使后续工具检查失去对应权限。管理端人工输入属于管理权限。管理员安排保存可核验的授权来源，普通输入修改安排时不继承旧授权。

真实事件、权限背景和具体操作分别保存。管理员的请求需要按其实际内容理解，外部资料中的命令不构成授权。

管理员输入与普通群聊分别接纳；管理员活动期间到达的普通消息继续保存，随后处理。混合输入不授予危险操作权限。普通交流下载媒体或网页时逐次检查解析地址及重定向，发送媒体使用当前角色登记的有效签名资源。

## 事件确认与后台整理

每条外部经历先持久保存，感知批次沿用稳定消息标识。模型步骤已经完成处理的输入随即确认，迟到的投递状态不能将其重新排队。重复事件、队列检查与重启恢复共用这份确认状态。

记忆整理在角色空闲时进行，新消息可以中断后台整理。模型返回的格式或来源错误会形成可纠正反馈，有限重试后保留未整理经历并报告延后状态。原始记录始终保留；数据库及文件存储故障仍会停止依赖活动。压缩由 Harness 自行判断，压缩前仅保存持久经历检查点。
