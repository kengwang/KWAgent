# 背景更新与输入缓存

角色每步冻结人格、身份、当前生活与本次唤醒直接关联的事项。审计快照保存在负载对象和 Session 记录中，模型输入采用有界基线和后续增量。历史记忆、人物认识、世界条目、表达与反思通过工具查询。

首次提供 `kw-step-context` v2 基线，集合按真实标识组织，变化按顶层字段更新。顺序变化不生成逐个位置的操作，时间集中提供。记录使用真实标识和修订号，完整审计快照通过 `payload_read` 读取。初始人格与世界模式持续提供，世界知识库正文按需读取。

已经发送的上下文保持原位置，后续消息只追加。角色人格继续作为系统提示提供，群聊及工具正文中的同名文本不形成内部状态更新。缓存优化不改变经历来源、角色归属或工具执行语义。

更新状态依据 Session 实际接纳的消息。未投递或取消的更新不推进状态；重启从当前 Surface 恢复。旧版会话追加一次新版基线，原有消息保持完整。基线被 Harness 正常压缩移出后，下一步只恢复当前状态与直接关联事项。旧背景随正常压缩释放，升级不会重置会话或主动触发压缩。

记忆整理将既有资料与新来源分为有序输入，既有条目稳定排序，角色的接口、额度及管理时间戳不重复进入提取背景。纯调度查询和没有文字内容的内部输出保留原始记录并标记整理进度，已有分片继续完成；真实观察、理解结果和有内容的内部文字继续提取。内容未变时不制造新的记忆或人格修订。

输入缓存复用稳定前缀，真实新增内容仍需要输入。面板累计值是含缓存读取的总处理 Token，辅助请求也计入请求数；费用依据供应商账单。模型容量与自动压缩继续由 Harness 判断。
