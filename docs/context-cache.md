# 背景更新与输入缓存

角色每步仍冻结完整的人格、生活、目标、记忆、来源与场合快照。完整快照保存在负载对象与 Session 记录中，模型输入采用基线和后续增量。

首次提供 `kw-step-context` 基线，记忆、人物、连续性和计划正文以内容引用登记；后续通过 JSON Patch 更新当前状态，仅补充尚未提供的正文。条目选择顺序、经过时间、失效及场合变化单独更新。模型使用当前选择的真实条目标识和修订号，完整内容继续通过 `payload_read` 读取。

已经发送的上下文保持原位置，后续消息只追加。角色人格继续作为系统提示提供，群聊及工具正文中的同名文本不形成内部状态更新。缓存优化不改变经历来源、角色归属或工具执行语义。

更新状态依据 Session 实际接纳的消息。未投递或取消的更新不推进状态；重启通过当前 Surface 中的基线与引用恢复。基线被 Harness 自动压缩或历史整理移出后，下一步重新提供当前完整基线。原始经历、旧修订和完整快照持续保存。

记忆整理将既有资料与新来源分为有序输入，既有条目稳定排序，角色的接口、额度及管理时间戳不重复进入提取背景。纯调度查询和没有文字内容的内部输出保留原始记录并标记整理进度，已有分片继续完成；真实观察、理解结果和有内容的内部文字继续提取。内容未变时不制造新的记忆或人格修订。

输入缓存复用稳定前缀，真实新增内容仍需要输入。面板累计值是含缓存读取的总处理 Token，辅助请求也计入请求数；费用依据供应商账单。模型容量与自动压缩继续由 Harness 判断。
