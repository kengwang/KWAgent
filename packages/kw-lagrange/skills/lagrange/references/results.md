# 结果与核实

Milky 成功响应通常为：

```json
{"status":"ok","retcode":0,"message":null,"data":{}}
```

MCP 可以同时返回文本内容和 `structuredContent`。优先阅读结构化结果。

## 失败类别

- 参数或协议失败：MCP `isError=true`。
- 业务失败：可能仍然 `isError=false`，内部 `status="failed"` 或 `retcode` 非零。
- 网络失败和超时：远程是否执行可能未知。
- Endpoint 通用异常：服务器没有提供具体异常，不能推断操作成功。

## 发送回执

群消息与私聊成功返回 `message_seq` 和 `time`。文件上传返回对应文件标识。使用这些值关联实际发送与后续查询。

## 结果未知

发送和上传没有客户端幂等键。再次调用可能产生重复内容。

1. 使用 `operation_read` 阅读自己的原操作记录与参数；省略 `id` 时列出最近记录。
2. 根据账号、会话、时间、内容和媒体查询实际结果。
3. 能确认成功时继续后续活动。
4. 无法确认时保留未知状态，再决定是否查阅更多信息或采取新的行动。

原有未知结果不会被新的尝试改写成成功。

消息和媒体的远程回执与实际客户端呈现分别核实；仅有编码路径时，保留实际验证状态。
